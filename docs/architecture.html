Skills Architecture

A self-improving agent skill system. Agents follow skill instructions, write retrospective notes when they finish, and those notes get distilled back into the skills — so every future run benefits from every past mistake.

Agent-agnostic Self-improving Cost-aware model routing

How a Skill Works

Each skill is a single SKILL.md file with YAML frontmatter and markdown instructions. The frontmatter is the contract between the skill and the agent runtime.

Skill Anatomy

---
name: wk:pr-resolve
description: |            # ← agent reads this to decide activation
  Address PR review comments interactively ...
model: opus               # ← default tier: opus or sonnet
allowed-tools:             # ← capability sandbox
  - Bash
  - Read
  - Edit
  - Write
metadata:
  version: '2026.04.22-070656'  # ← CalVer (not semver)
  model:
    openai:  o3               # ← per-provider model overrides
    google:  gemini-2.5-pro
    meta:    llama-4-maverick
    cursor:  composer-2
---

# Instructions follow as markdown ...

Lifecycle: One Skill Execution

01

Trigger

User types /wk:name or agent auto-detects via description match

02

Load

Runtime reads SKILL.md, applies tool allowlist and model selection

03

Execute

Agent follows markdown instructions step by step

04

Reflect

Post-completion hook: agent reviews what went wrong, what was missing

05

Capture

If notable: write learnings/.../date_slug.md

Agent-Agnostic Model Routing

Every skill declares a default tier and a per-provider override table. Complex reasoning tasks get high-tier models. Procedural tasks get cheaper models. No code changes needed to switch providers.

How It's Wired Up — Tips

🔁

Post-completion hook — baked into every skill

The last section of every SKILL.md instructs the agent to reflect and write a learning. There's no separate hook system — the skill itself carries the instruction, so it works on any agent and any platform.

🌍

WK_SKILLS_HOME points to this repo

Add export WK_SKILLS_HOME=$HOME/gitc/skills to ~/.zshrc. Every skill's learning hook writes relative to this path. Without it, the hook silently fails.

⚡

wk:sharpen runs in two modes

Single: /wk:sharpen pr-resolve incident.md — targeted fix. Batch: /wk:sharpen — scans all unprocessed learnings and global memory feedback files, processes up to 5, logs results.

🏷️

Versions are CalVer, never semver

Every skill version is a UTC timestamp: 2026.04.22-070656. Run /wk:calver before bumping any version field. Semver is explicitly forbidden in this repo.

🛡️

allowed-tools is a capability sandbox

Each skill declares exactly which tools it needs. The runtime enforces this allowlist. A retro skill can't accidentally run destructive bash commands because those tools aren't in its list.

💰

Model routing controls costs

Procedural skills (retro, commit, calver) declare model: sonnet and map to cheap models per provider. Reasoning skills use model: opus. The agent runtime picks the right model — you never hard-code it.

📦

After editing, reinstall globally

Run npx skills add . -g -y -a=claude from the repo root after any skill change. This syncs changes to ~/.claude/skills/ where the agent reads them at session start.

🔍

The description field is the trigger

Agents read the description: frontmatter to decide when to activate a skill. Write it like a search query: specific trigger phrases, use cases, and what NOT to trigger on. Vague descriptions cause false positives.

🌐

Works across 40+ agents

Skills follow the open Agent Skills spec. The same SKILL.md works in Claude Code, Cursor, Copilot CLI, Gemini CLI, and others. Platform differences are handled by the frontmatter model overrides.
