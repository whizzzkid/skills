# Extended Mechanical Sweep Catalog

Part of the Step 2 catalog — apply each row under the **same unconditional rule**
as the inline catalog whenever its trigger matches. These are lower-frequency,
shape-specific sweeps relocated here to keep `SKILL.md` under the body-size
ceiling; relocation does not lower their priority.

| 2.9.2 | Spec introduces an event-sourced materialized-view / dual-write (table + event log) | Four contract failure modes look like one: (a) is "authoritative" scoped to mutations-only or all-writes? — a creation baseline written straight to the table with no event breaks event-replay reconstruction; (b) is every write path (create, ingest, re-ingest, webhook, reaction) enumerated and assigned event-first or baseline-only? — an undifferentiated re-ingest silently mutates user-facing columns outside the event log; (c) is "atomic" backed by an explicit transaction, not just the HTTP request boundary? — two sequential writes partially commit on crash/drop/exception between them; (d) is the fold ordering deterministic under same-timestamp writes? — `created_at` alone collapses, use `(created_at, id)`. | Blocker | Scope authority explicitly; enumerate+assign every write path; require a transaction or flag partial-commit risk; tie-break the fold by `(created_at, id)`. | 2.52 | Helper extracted from / wired to accept `context.Context` | Grep the helper body for `context.Background()`/`context.TODO()` when the calling function takes a `ctx context.Context`/`parentCtx` param — caller-supplied cancellation (SIGINT, timeout) is silently dropped. A `Canceled` case that became unreachable confirms the context was never plumbed; asymmetric coverage vs a sibling function is a signal. | Blocker | Add `parentCtx context.Context` as the helper's first param with a `nil → context.Background()` guard; handle both context error cases when cancellable from outside, matching the sibling. |
| 2.54 | Build script passes `-ldflags "-X pkg.Symbol=value"` (or any stringly-typed cross-language symbol contract) | The symbol name is an unchecked contract between the builder and the consuming language; a string-match assertion in the builder's own test does not lock the symbol name or output path, and a rename on either side passes both suites silently. | 2.59 | Diff adds/extends a generator or automation that writes a value (count, version, enumerated list) into a file | The tool is now the source of truth for that value — grep every other file for the same value and confirm the same automation updates each consumer. | 2.20 | Application code + CI pipeline | Extract net-new env reads; locate invoking pipeline steps; verify allowlist forwarding. | 2.61 | Diff deletes a file | For every deleted file, grep the entire repo (comments, docstrings, string literals — not just code/symbol references) for the deleted file's basename. | 2.62 | Diff adds/edits a `rescue`/`catch`/`except` block that calls a typed API (sorbet sig, TypeScript, mypy, typed Go params) | The error path must satisfy the same typed-argument contract as the happy path — a sweep that checks only happy-path signatures (2.7) misses it because a handler reads as defensive. Grep the callee signature; verify every argument type, especially an identifier/class/module param a plain String could be wrongly passed for. A raise inside a handler (e.g. `TypeError`) converts a soft-fail into a hard crash at the moment of degradation — strictly worse than the error it handles. | Blocker | Fix the argument type to match the sig so the handler cannot raise. |
| 2.63 | Diff touches a shell script | Three recurring quoting/precedence gaps a symbol sweep misses: (a) a flag/arg list built as a whitespace-joined string (esp. `echo "$x" \| xargs -I{} echo --flag={}`) then re-expanded unquoted → word-splits any path with spaces; (b) `\|\| true` immediately followed by a pipe — `\|` binds tighter than `\|\|`, so the stage after the pipe is dead code; (c) an external command (e.g. `tput`) on a success path under `set -e` aborts when it fails or `$TERM` is unset/dumb. | Blocker | Build arg lists as a bash array expanded `${arr[@]+"${arr[@]}"}`; parenthesize the `\|\|`-guarded command so the pipe does not regroup; guard success-path external commands with `2>/dev/null \|\| true`. |
| 2.64 | A readiness/mergeable claim follows a bot re-review | A bot can post blocker-severity findings only in its top-level summary comment (`issues/comments`), with no inline `reviewThreads` entry — "no new inline threads" is not "no new findings", and green CI does not mean mergeable. | Blocker | Fetch `mergeStateStatus`/`reviewDecision` directly (source of truth) and grep the latest bot issue-comment/review body for severity markers ("Major", "blocker") before declaring ready; never infer mergeability from CI status or inline-thread count alone. |
| 2.65 | A guard/type pattern appears ≥2× in one file, applied inconsistently | Intra-file symmetry of an established pattern — each line looks locally fine, so a general pass misses it. Two recurring shapes: (a) a `grep`/pipeline appearing ≥2× in one shell script under `set -e`+`pipefail` where one instance carries a `\|\| true` match-failure guard and a sibling does not (empty grep → exit 1 → pipefail aborts the script); (b) sibling methods in one RBI/type class bind a block/proc to a receiver (`T.proc.bind(Klass).void`) while another sibling uses an unbound `T.proc.void`, losing type precision. | Suggestion | Apply the established guard/binding to every sibling instance in the file, or justify the difference. |
| 2.66 | Diff parses an `Authorization`/`WWW-Authenticate` header (auth-scheme + credentials) | RFC 7235 defines `auth-scheme` as case-INSENSITIVE and the scheme/credentials separator as `1*SP` (one-or-more spaces). A regex matching a fixed-case scheme literal (`Bearer`) or a single literal space is non-conformant — it passes mechanical review but rejects valid clients. | Suggestion | Match the scheme case-insensitively (`/i`) and the separator as one-or-more spaces (`\x20+`/`\s+`); real clients usually send canonical casing + one space, but a conformant server must accept both variants. |

| 2.69 | Test asserts "accepts every valid enum value" by looping the same constant that *defines* the enum (e.g. `enum :x, CONST.index_by(&:itself)` with `build(...).valid?` over `CONST`) | Tautological — the accepted set is `CONST` by construction, so the loop can never fail; it also misses a dropped `validate:` flag and (since `build` never persists) any DB CHECK-constraint drift. | Blocker | Require (a) `create`/persist so DB CHECK constraints run, and (b) an independent exact-match assertion (`expect(Model.xs.keys).to match_array(Model::CONST)`) guarding enum drift — never a loop over the defining constant. |
| 2.70 | Nil-guard added for a schema-nullable structured column (JSON/JSONB/`hstore`, or a Go map from `json.Unmarshal`) | A non-nil-only guard (`&.`, `.fetch`, `x != nil`) still crashes on a wrong-shaped value: the same out-of-band writer (absent key, backfill, migration) that yields nil can yield a JSON array (`TypeError`) or scalar (`NoMethodError` on `#fetch`). | 2.72 | A finding proposes replacing `T.untyped`/`any` with a precise type on a param/return | Infeasible if the framework's type stubs (RBI/`.d.ts`) don't declare a member the body dereferences on that type — runtime-added accessors (framework mix-ins/metaprogramming) are the blind spot, and a linter-banned `T.unsafe`/`any`-cast leaves no bridge. | 2.75 | A broad `rescue <ParentError>` returns a fail-closed default (empty/deny/nil) for the whole hierarchy | Fail-closed conflated with fail-silent: some subtypes are the documented steady state (deny quietly), others are should-never-happen config/deploy bugs that will never self-heal and must page.
