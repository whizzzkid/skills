- **Rule:** When a new skill is framed as replacing/superseding/deprecating
  existing skills, read each superseded skill's SKILL.md, extract its feature
  list, and confirm the new skill covers each (or records an explicit
  exclusion) before declaring it done.
- **Why:** Features left implicit surface one-by-one across later real runs,
  each forcing a separate follow-up sharpen pass; reference coupling also means
  the superseded file must be kept (deprecated) when linked as a spec source.
- **Where:** wk-skill Step 6 — HARD RULE "supersede parity audit".
