**Rule:** A land-intent invocation ("land this" / "make it merge-ready" /
"resolve to merge") is standing authorization for the whole resolution lifecycle
— posting replies AND resolving worked-on threads, not just pushing. Do not split
an already-authorized action into a fresh per-action confirmation ask. Reserve the
confirmation ask for a bare "resolve comments" with no land intent.

**Why:** Hard Rule 1 already granted standing authorization for *pushes* on a
land-intent invocation, but Hard Rule 2 (never post replies without confirmation)
carried no matching carve-out. The agent read Hard Rule 2 literally and re-asked
"may I post replies / resolve threads?" after the user had already invoked the
resolve-and-land workflow — a redundant re-ask that reads as unpredictable.

**Where:** Hard Rule 1 (standing-authorization clause, broadened from pushes to
the whole lifecycle) and Hard Rule 2 (pointer back to it).
