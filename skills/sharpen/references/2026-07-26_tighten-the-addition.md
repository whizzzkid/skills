# The addition is a reclaim target too — the third move at an exhausted pool

**Rule** — When categories 1–4 of the reclaim search are exhausted and net is still
positive, tighten the **addition** before reporting the arithmetic and instead of widening
the hunt. A draft's first size is an estimate, not a requirement, and it is the only lever
that cannot endanger existing load-bearing content.

**Why** — Every reclaim target the rules name lives in the target file's *existing* content
(search duplicates, relocate a catalog block, prose-tighten), and the escape hatch when
those run out is framed purely as reporting. Read literally, a run facing an exhausted pool
has exactly two exits — stop without folding, or widen into content the same rules forbid
touching — so it treats its own draft as immovable and calls the fold unlandable. That is
the identical standoff the measured-allowance rule was added to dissolve, one step further
along.

**Verified against source** — Confirmed before drafting:

  returned **zero** across both `SKILL.md` and the linked [`byte-budget.md`](byte-budget.md);
  a positive control on a known-present phrase from the same bullet returned a hit over both
  files, so the zero is real and not a mis-resolved path. Both paths were confirmed to exist
  first.
- The reporting learning's arithmetic reconciles exactly against the prior fold's own record

  gross 605 B → 242 B and net +487 B → +124 B are the same two cuts measured with and
