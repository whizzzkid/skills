Design spec for a new `wk-sitrep` skill — a unified daily ops log backed by a
SilverBullet workspace instead of generated HTML/markdown files.

**What it replaces:** `wk-goodmorning` and the former evening sitrep flow as standalone skills;
eliminates the morning-triage step and all HTML-generation steps, since
SilverBullet renders markdown in the browser live.

**Architecture:**

- Dedicated SilverBullet repo with a workspace path at `$SITREP_REPO`; all
  pages written under `$SITREP_REPO/$EMPLOYER/`.
- Single persistent daily file: `$EMPLOYER/live.md` — appended-to all day,
  checkbox-driven, opened in the browser at `<localhost>/$EMPLOYER/live.md`.
- End-of-day snapshot: `$EMPLOYER/YYYY/MM/DD/snapshot.md` generated by
  scrubbing `live.md` — done items stripped from live, everything preserved
  in the snapshot.

**Sub-commands:**

`wk-sitrep start` (runs at workday start, whenever that is):
- Fetch Slack unreads, Gmail, Calendar events, Granola notes, GitHub
  PRs/issues needing attention (everything `wk-goodmorning` does).
- Carry forward incomplete items from the previous `live.md` (not-done
  checkboxes) into today's live.md under a "Carry-over" section.
- Prepend today's agenda (calendar blocks, scheduled meetings) and the
  priority inbox (messages needing response, follow-ups).
- Write/overwrite `$EMPLOYER/live.md` with the full daily brief.
- Open `<localhost>/$EMPLOYER/live.md` in the browser (`open <url>`).

`wk-sitrep end` (runs at workday end, not tied to clock):
- Read the current `live.md`.
- Generate `$EMPLOYER/YYYY/MM/DD/snapshot.md` — full capture: achievements,
  brags, PRs merged/reviewed, meetings attended, feedback snippets, carry-over
  items (done + pending), Granola notes.
- Scrub `live.md`: remove completed checkboxes, keep open items for tomorrow's
  carry-over.
- Update brag doc and any Lattice feedback-request stubs (everything
  wk-sitrep end does).
- Confirm snapshot written and live.md pruned.

**SilverBullet integration notes:**
- SilverBullet serves pages at `http://localhost:<port>/` by default; the
  `open` call should resolve the port from the running process or a config var
  (`$SITREP_PORT`, default 3000).
- No `Write` tool writes outside the skill's designated repo path; never touch
  other project files.
- The skill should verify the SilverBullet server is running before writing
  and optionally start it (`silverbullet $SITREP_REPO`) if not.

**Suggested fix / next step:** Build via `wk-skill sitrep` using this spec as
the body source. Reference `goodmorning/SKILL.md` and the former evening sitrep
flow for the data-fetching steps rather than copy-pasting them inline.
