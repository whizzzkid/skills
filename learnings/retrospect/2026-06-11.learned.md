
## Session-1

### What worked
- Parallel CI watch + self-review reduced total PR-ready time; CI finished before self-review was posted.
- Independent mechanical sweep (dead-import grep) caught a real blocker the adversarial subagent explicitly cleared as "no dangling refs" — the subagent verdict is not a sufficient substitute for mechanical sweeps.
- Aborting a failed autosquash rebase and leaving the wasm rebuild as a separate conventional commit was the correct fallback when non-interactive `GIT_SEQUENCE_EDITOR=:` re-triggered all conflict resolution from the new base.

### What could've been better
- wk-workflow: when a branch has an open PR, resolve `baseRefName` via `gh pr view` before planning any rebase — never assume the default branch is the target.
- wk-adversarial-review: `GIT_SEQUENCE_EDITOR=:` with `--autosquash` replays from the base rather than folding within the existing chain; document this footgun so future runs use `git commit --fixup` + amend approach instead.

## Session-2

### What worked
- Adversarial review caught a second-order fix gap (permissive `else . end` in a jq type-guard) that the initial bot review and the first fix both missed; applying suggestions inline before push prevented a third review cycle.
- Playground validation against all 7 jq edge cases (array, scalar, null, missing, empty array, mixed, malformed) gave high confidence before committing.

### What could've been better
- adversarial-review: Initial jq fix used `elif . == null then empty else . end`, leaving the `else` branch permissive for object inputs; the correct pattern for safe multi-type field extraction is `elif type=="string" then . else empty end` — restrict to the expected type, not just to non-null.
## Session-3

### What worked
- Adversarial review in auto mode correctly applied both suggestions (weak assertion, missing test variant) inline before push — no second review cycle needed.
- Prior clearance record let re-invocation skip re-examining unchanged commits, keeping the review gate fast.

### What could've been better
- [pr-resolve]: bats symlink-escape tests must use a known-to-exist symlink target (`/etc/passwd`); `-f` follows symlinks and returns false for dangling links, silently bypassing the security guard branch.
- [adversarial-review]: test-only commits need explicit path-variant coverage audit — enumerate distinct code paths in the function under test and verify each is exercised, not just that tests exist.

## Session-4

- Auto-transitions for two tickets succeeded on first attempt via MCP.

## Session-5

### What worked
- Adding an enforcement hook in the same pass as conforming existing files to it surfaces every violation immediately and proves the hook against the real corpus.
- Distilling an unprocessed learning before renaming it to .learned.md, rather than blind-renaming, prevents orphaning the lesson.

### What could've been better
- wk-commit: a pre-staged `git mv` rides into the next `git commit` regardless of the explicit `git add` paths — verify `git diff --cached` matches the intended group before committing (routed to wk-learn).
## Session-7

### What could've been better
- wk-adversarial-review: enumerate all affected sites via grep before writing any code for a cross-cutting change — then implement all at once; iterative partial-fix + review produced 5 commits and 3 review rounds instead of 1-2.
- wk-workflow: hold commits for a cross-cutting change until the complete site map is implemented; one adversarial review on the full implementation, not one per partial commit.

## Session-7

### What worked
- Three-surface PR comment fetch (inline + review bodies + issue comments) caught a bot review only in the issue-comments surface — would have been missed with inline-only fetch.
- Routing adversarial-review learnings immediately after the goimports fix (before the retro) kept the capture precise; the retro scan confirmed no additional interruptions to mine.

### What could've been better
- adversarial-review: after a struct field type is widened, the sweep should run `goimports -l` on the file as a mechanical blocker check — the current sweep catches logic/security but not gofmt-family alignment regressions.
- workstyle-go: widen type name on a struct field → must re-run `goimports` on the whole file, not just format-on-save with `gofmt`; partial format passes `gofmt` but fails CI's `goimports` check.

## Session-8

### What worked
- Scoping the adversarial re-review to new commits since the cleared SHA kept the pass fast and targeted.
- Logical commit grouping (one commit per component: agent module, script, poster, docs) made the blocker-fix commit surgically small and easy to review.

### What could've been better
- adversarial-review: When implementing a two-store fallback (`primary || secondary`), the coverage gate should require a test where the primary returns a truthy-but-invalid value AND the secondary returns a real value, asserting the secondary reaches the caller. Without that test the fallback-bypass bug is undetectable.
