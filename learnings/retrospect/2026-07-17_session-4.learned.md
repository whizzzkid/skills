## Session-4

### What worked
- Running `git diff --check` and a rerere-aware conflict inspection before trusting a merge's staged resolution catches auto-applied resolutions that silently drop the branch's own changes.
- Comparing rubocop offenses on pre-merge vs post-merge versions of an auto-generated file confirms the merge introduced no new offenses.

### What could've been better
- pr-update: a stale rerere cache can silently re-apply a prior wrong resolution to an auto-generated file (schema dump) — always `git rerere forget <file>` and re-inspect real conflict markers when a merge reports "Staged <file> using previous resolution".
