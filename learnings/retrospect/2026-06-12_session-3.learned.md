## Session-3

### What worked
- Adversarial review caught three distinct blocker classes (stale Q&A reference, cross-field vocabulary mismatch, routing claim vs authoritative reviewer statement) in a docs-only PR — reinforcing that the gate applies to spec docs, not just code diffs.
- Real-time `wk-learn` captures at each fix moment produced precise learning files; deferring to retro would have lost specificity.

### What could've been better
- wk-adversarial-review: Q&A / open-questions sections were not treated as first-class grep targets when a struct field was removed — hit open-question stale reference that prose sweep missed (filed: `adversarial-review/2026-06-12_open-question-stale-field-reference.md`).
- wk-adversarial-review: struct field comment drift — fix applied at the requirement site but not at the stored-shape declaration site; two canonical names coexisted for the same values (filed: `adversarial-review/2026-06-12_structured-return-field-comment-drift.md`).
- wk-adversarial-review: routing claims in spec prose must be cross-checked against authoritative reviewer statements before asserting — inference from logic is not ground truth when reviewer has read the source (filed: `adversarial-review/2026-06-12_routing-claim-vs-reviewer-feedback.md`).
