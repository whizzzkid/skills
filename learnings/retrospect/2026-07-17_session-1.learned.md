## Session-1

### What worked
- Ground-truthing every concrete code claim in a spec via one verification subagent before drafting review comments caught a factual "existing infrastructure" inaccuracy.
- Re-verifying a posted finding the moment a later tool result appeared to contradict it, rather than letting the stale claim stand.

### What could've been better
- wk-arch-review: lens findings on executable logic were returned as conclusions without ever running the logic; add a mandatory empirical/simulation pass for logic-bearing specs.
- wk-pr-review: skipped the wk-adversarial-review simulation step and composed comments from static analysis; always run the empirical pass when the change contains executable logic.
- wk-pr-review: a new finding was buried in a reply on an unrelated thread instead of its own line-anchored comment.
- wk-pr-review: opened a second pending review for one incremental comment on an already-submitted review instead of posting it directly.
- wk-pr-review: review body restated findings already posted inline, and claims used bare first-person instead of explicit agent attribution.
- wk-gh: review body opened with a praise adjective ("Solid, well-grounded") instead of the verdict state (LGTM / approving with concerns).
