## Session-1

### What worked
- Tracing the root cause across config layers (YAML defaults vs. Secrets Manager null overrides) without running the app — reading the config file + application.rb together was enough to identify the boot failure path
- Adversarial review caught a real security gap (length-leaking `secure_compare`) that the first implementation missed; the fix-then-re-review loop worked correctly and stayed scoped to the delta
- RuboCop failure in CI was immediately diagnosable from job logs without a second push; targeted single-line fix, re-push, green on next build

### What could've been better
- wk-pr: PR body did not prominently state that the code change does NOT fix the triggering symptom (health-check failure); user had to ask mid-session to understand the relationship between the security fix and the infrastructure root cause
