## Session-4

### What could've been better
- pr: merge/dependency order for a PR stack must be derived from each PR's actual `baseRefName` (`gh pr view --json baseRefName`), never from part-N labels or memory — deriving it from labels fabricated two dependencies that did not exist in the base graph.
- pr-break: when a stack's dependency graph is reordered (a later part re-parented onto an earlier one to fix ordering), the part-N numeric labels no longer match merge order and become an actively misleading source of truth; renumber the labels or drop ordinal labels entirely so order is only ever read from bases.
