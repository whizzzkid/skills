## Session-1

### What worked
- Re-running a structural invariant as an executable check (expand every glob, resolve every relative link, count headings against graph nodes) after each commit caught two defects that reading the diff did not.
- Preserving the bodies of an orphaned pending review to a temp file before deleting it made the delete safe and let the re-staged version fix the two bullets that had gone stale.

### What could've been better
- wk-arch-review: never promote a value that is still a placeholder elsewhere in the same document set into a section headed "resolved" or "pin exactly" — mark the cell unresolved and name the item that resolves it, because a wrong-but-internally-consistent pair passes every consistency assertion.
- wk-adversarial-review: treat a documented glob or brace path as executable — expand it and assert a non-zero match count, since a path pattern that matches nothing reads as a valid reference in review and only fails for the agent who later runs it.
- wk-adversarial-review: never assert a shell exit status in a doc without running it on the target platform — `grep -s` over a missing path exits 2 on BSD and 1 on GNU, so a status-based gate passes or fails by machine; judge such checks on output instead.
- wk-commit: a PR-body sync is not complete until the outbound-footer gate is re-run on the new body — the commit-message trailer and the canonical outbound footer are different strings, and a body carried over from an earlier revision keeps the wrong one.
- wk-self-review: detect an orphaned pending review by comparing each comment's `position` against `original_position`, not only the review's `commit_id` — pending comments report a null `line`, so drift is invisible unless the two position fields are compared.
