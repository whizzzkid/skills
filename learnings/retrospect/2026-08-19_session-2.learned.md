## Session-2

### What worked
- Reproducing a bot-reported claim directly (spinning up the actual container image) before accepting or dismissing it caught a false positive and avoided an unnecessary code change.
- Detecting a pending self-review before attempting reviewer replies, then submitting it first per explicit user instruction, avoided the silent-swallow failure mode where replies land invisibly inside a draft review.

### What could've been better
- pr-resolve: the reply-to-review-comment REST endpoint requires the pull-request number as a path segment (`/pulls/{n}/comments/{id}/replies`); omitting it (`/pulls/comments/{id}/replies`) returns a generic 404 with no hint about the missing segment, costing a wasted round-trip.
