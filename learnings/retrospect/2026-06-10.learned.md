
## Session-1

### What worked
- The dual-index enforcement hook (`check-readme-index`) blocked every future skill-add without a row immediately and required no manual reminder.
- Running `git filter-repo` with a replacements map scrubbed all tokens from blobs and commit messages in a single pass; 0 hits post-rewrite verified.
- All pre-commit hooks (7+ runs) passed after targeted fixes with no re-rerun needed beyond the initial bash-compat fix.

### What could've been better
- wk-workstyle-shell: hooks written in bash must be probed for macOS system bash (3.2) compat — `mapfile` is bash 4+ only and fails immediately on the default macOS shell; use a `while read` loop instead.
- wk-skill: bare `wk-<name>` example identifiers in a skill's own README must use relative markdown links from the first draft — a plain backtick example trips the link-check hook and forces a re-commit.
- wk-sharpen: when replacing a set of tokens where some are substrings of others, process longest-first — replacing a short token before its longer sibling corrupts the longer one.

## Session-2

### What worked
- All seven pre-commit hooks fired correctly on every commit, including the two new ones (`check-usernames`, `check-pr-numbers`) self-testing against their own content.
- filter-repo PR-context regex preserved CSS hex colors perfectly.
- `Assisted-by:` dogfooding: the wk-commit update commit itself carried the new trailer.

### What could've been better
- wk-sharpen: when a `git filter-repo --replace-text` map includes patterns where one is a substring of another, the replacement-order rule (longest-first) must also apply to the *map file* — re-running the map against its own examples can corrupt them (the existing replacement-order rule covers new SKILL.md edits but not the filter-repo map itself).
- wk-retro: the `>>` heredoc append pattern fails silently in zsh when `$FILE` contains a space or when the HEREDOC marker is not matched — use an explicit `cat >> "$FILE" <<'EOF'...EOF` with simple quoted marker, or write to a temp file then append.

- Shared `let` extraction in the spec removed three verbatim blocks without any test regression.

### What could've been better

- [pr-resolve]: During adversarial review setup, avoid `git status` — the diff is already known from the commit step; `git status` here is superfluous and reads as uncertainty.
