## Session-1

### What worked
- Brainstorming → arch-review → adversarial-review → RFC rewrite cycle produced a cleaner doc than any single-pass authoring; running both reviews and folding findings without asking produced the most useful PR.
- Dispatching a fresh adversarial subagent (code-reviewer agent type) for the re-review after mermaid fix caught five real bugs: missing wave-diagram edges, link-text mismatch, write-interception gap, cross-epic dependency not surfaced.
- Verifying a single pilot Jira story before batching 15 more prevented schema surprises (parent-link format, label structure).

### What could've been better
- wk-arch-review: doc-quality checklist (frontmatter, Diátaxis structure, diagram discipline, link validation, no fabricated sizing) was not enforced — multiple revision rounds needed before spec was RFC-ready.
- wk-pr: agent stopped to ask whether to incorporate arch-review/adversarial-review findings instead of applying them unconditionally.
- wk-brainstorming: spec was written before user gave structural feedback (Diátaxis framing, diagram structure, link hygiene, sizing) — structural conventions should be enforced at write-time, not discovered through user review.
