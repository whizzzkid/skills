## Session-2

### What worked
- Run a negative control (restore the original view, expect the new specs to fail) before trusting new UI specs; it proved all three new examples were load-bearing.
- Verify every browser-behavior claim made in a code comment (hover refresh timing, contrast ratios) with a live measurement before committing it; one assumed ratio was corrected this way.
- When sibling PRs insert at the same anchor, stack the later one on the earlier and merge the parent in once, so each PR's diff stays scoped and the final merge to the default branch is one-sided.

### What could've been better
- workflow: Treat "same box/size as the neighbouring controls" as identical rendered width and height, and assert equal bounding boxes for every variant in the browser before claiming it.
- pr: Run the browser-open for each PR immediately after its create call; it was skipped for every PR in a multi-PR session.
- playwright: After any visual fix, regenerate every screenshot the PR references in one re-runnable script and delete superseded captures; stale pre-fix captures read as a failed fix.
- pr-update: When asked to confirm nothing broke after a verbatim conflict resolution, run a read-only measured behavior check instead of regenerating evidence, and back up evidence before any overwriting capture.
