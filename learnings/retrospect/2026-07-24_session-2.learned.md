## Session-2

### What worked
- Splitting a schema-bound bug into a clamp PR and a widening PR stacked on it kept each PR independently green and made the migration reviewable on its own.
- Recording the one-run match-key cost in an ADR before opening the PR meant the reviewer-facing risk note, the PR body, and the ticket comment all cited the same written source instead of three paraphrases.
- Running the base-detection algorithm rather than assuming the default branch caught a genuinely stacked branch that "obviously" looked trunk-based.

### What could've been better
- bash: a presence check written as `${VAR:+yes}${VAR:-NO}` printed a live credential, because the default expansion emits the value on the set path — presence checks must use a test builtin, never a value expansion.
- pr: the base-detection snippet's `for CAND in $CANDIDATES` word-splits a newline-separated branch list and returns the sentinel detection failure; the read-loop form resolves it.
- buildkite: a green top-level check rollup was treated as per-job evidence; only the per-job CLI view can support a claim that a specific job passed.
