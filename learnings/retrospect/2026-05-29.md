## Session-1

### What worked
- Capture a skill gap the moment it surfaces (wk-learn in the same turn as the correction), not at retro time.
- Treat a category flagged by multiple reviewers within one cycle as one incomplete-fix signal, not independent findings.

### What could've been better
- wk-pr-resolve: never emit an `(a)/(e)/(d)/(s)` prompt when the skip rationale is empty / "no valid reason" — apply directly, regardless of finding severity or source.
- wk-pr-merge: do not exclude self-review threads from the unresolved-thread count — branch protection blocks the merge on any unresolved thread.

## Session-2

### What worked
- When adopting an automation-authored PR with remaining work in another repo, locate that repo locally before dispatching; cross-repo changes need two cross-linked PRs.

### What could've been better
- wk-pr-resolve: read and fully implement any handoff doc (e.g. RUN_LOCALLY.md, NEXT_PHASE.md) before deleting it.
- wk-pr-resolve: verify a new request spec includes auth headers matching sibling tests before pushing to CI.
- wk-adversarial-review: flag the nil/blank branch of a presence-guarded builder method as uncovered when all fixtures supply valid values.

## Session-3

### What worked
- Frame each problem in a spec by its user-facing symptom rather than its internal cause — it produces sharper solution-space discussion.
- Renumber all downstream cross-references in the same commit as the item renumber — never defer cross-ref cleanup.

### What could've been better
- wk-slack: write Slack mrkdwn from the start (`*bold*`, `~strike~`) — the send tool does not convert standard Markdown.

## Session-4

### What worked
- Compare conflict complexity against a rebase dry-run before committing to manual resolution.
- Auto-merge queue (`--auto`) is the correct path when branch protection gates a direct merge.

### What could've been better
- wk-pr-update: add a conflict-complexity dry-run step before committing a full manual resolution.
- wk-pr-resolve: a script that keeps "both sides" of a split test file can splice mid-function bodies — require a manual verification pass after automated merge.

## Session-5

### What worked
- Read the runtime code to confirm a system actually consumes its declared config/frontmatter before accepting a doc's behavioral claims.

### What could've been better
- wk-pr-review: trigger wk-arch-review unconditionally for `docs/(specs|adr|arch|design|rfc)/` paths — doc-only is not a skip signal.
- wk-pr-review: classify committed machine-local paths (home dirs, worktree refs) as blocker, not suggestion.
- wk-arch-review: probe whether declared frontmatter/config is actually consumed by the runtime (lens C).
- wk-workflow: capture learnings automatically — never ask permission.
