## Session-2

### What worked
- Reproducing an externally-sourced review finding before fixing it confirmed both bot findings were real defects rather than style nits, and produced the regression test as a by-product.
- After a history rewrite, hunting every place a commit SHA had been recorded (plan doc, PR body, tracking issue) and re-verifying each with an ancestry check left zero stale references.
- Reviewing a docs sync commit against its *effect* on the whole document, not just its own diff, caught a sibling status row that the sync had silently made false.

### What could've been better
- wk-commit: trailers were copied from sibling commits on the branch instead of decided from the skill's own rules, adding an unwanted human co-author trailer to every commit and forcing a full-branch rewrite that invalidated every recorded landing SHA.
- wk-gh: no pre-flight read of repository rulesets, so a squash-only merge-method restriction — invisible to both the classic branch-protection endpoint and the repo-level merge-method fields — surfaced only when the merge was refused.
- wk-pr: a CI run id was written into the PR body's test-plan checkbox from context rather than pasted from a command run in that same turn, producing a link to a run that does not exist.
