## Session-1

### What worked
- `<span onclick>` as a custom checkbox pattern bypasses the editor's form-element disabling
- `window.client.space.readPage/writePage` is the correct file I/O API — handles all sync layers
- CSS `:has()` for state-based styling without JavaScript is clean and persistent
- No-blank-line HTML blocks keep content inside the widget and render inline markdown (bold, links)
- `String.fromCharCode(34)` solves the double-quote-in-attribute-value problem reliably
- Playwright browser automation was effective for iterative DOM inspection and debugging

### What could've been better
- wk-silverbullet: `<input>` disabled by editor was not known upfront — 2 iterations wasted on form elements
- wk-silverbullet: service worker intercepts fetch was not known — 3 iterations wasted on HTTP API guessing
- wk-silverbullet: CommonMark blank-line HTML block rule was not known — 1 iteration lost to broken column layout
- wk-silverbullet: `>` in arrow functions inside attribute values truncates — caught only after DOM inspection
- wk-sitrep: original skill spec mandated markdown table with ⬜ glyphs; interactive checkboxes were not an original design goal but became a requirement — skill should note the div-based recipe as the preferred layout
