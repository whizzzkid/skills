## Session-9

### What worked
- Inverting a stack's parent/child via `git rebase --onto <new-base> <old-base> <branch>` re-parented branches with zero conflicts when the two branches touched disjoint file sets (data-only frontmatter vs. code-only).
- After a force-push moved HEAD, deleting and re-posting the pending self-review anchored to the new HEAD SHA preserved every inline comment the orphaned review would have lost.

### What could've been better
- pr: when slicing a PR stack, a gate/enforcement PR that requires data must be sliced downstream of the PR that provides that data — otherwise the gate PR is CI-red in isolation and the stack needs rebase surgery to reorder.
