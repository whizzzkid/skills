## Session-1

### What worked
- Run an independent adversarial review in parallel with CI as soon as the PR is published: it found a boot-time crash that no CI step could exercise.
- After fixing a flaw, sweep sibling sites for the same flaw class before pushing, so the next reviewer round has nothing left to find.
- Read the CI log, not just the job state: it separated a green spec run from a failing coverage gate.

### What could've been better
- wk-workflow: an environment blocker (registry auth) should block only the verification gates, never implementation; implement first, then surface the blocker scoped to what stays unverified.
- wk-workflow: when a fix adds an edit that another edit depends on, name the coupling invariant and gate both edits on every precondition, with a sad-path test per precondition.
- wk-workflow: do not chain commands with `&&` in one shell call; split dependent commands into sequential calls.
- wk-buildkite: a CI watch must resolve its own target build and survive transient API failures, rather than hardcoding build numbers that are hand-edited after every push.
