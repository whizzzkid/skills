## Session-3

### What worked
- When a user recollection contradicted verified source-reading (a claimed cache TTL), re-checking the actual config-library source and grepping for TTL-related terms before responding — then presenting the code evidence directly rather than deferring to the recollection — surfaced the real answer instead of compounding an unverified claim.
- Before trusting a subagent's claim about a logging library's behavior (whether a Hash argument produces structured JSON facets), reproducing it empirically against the live app rather than reasoning from memory about `Logger` internals confirmed the claim and drove a concrete fix.

### What could've been better
- wk-gh: constructing a JSON request body for a `gh api ... reviews` POST via a bash heredoc with manually escaped quotes/backticks caused an HTTP 400 ("Problems parsing JSON"); building it with `jq -n --arg ...` instead avoided manual escaping entirely and should be the default approach for any `gh api` POST with a non-trivial body.
