## Session-1

### What worked
- Layered regression chain argument (pre-condition lock → data-flow lock → serialization lock) effectively justified dismissing an E2E test-coverage bot finding without adding impractical tests that require live API calls.
- Bot thread GraphQL fallback (top-level comment + `resolveReviewThread`) handled unstable REST IDs cleanly when the bot replaced its review mid-session.

### What could've been better
- wk-gh: GraphQL queries used a URL-derived repo name (hyphenated) instead of the actual stored repo name (underscored), causing a `NOT_FOUND` error; always resolve via `gh repo view --json name` before any GraphQL call.
