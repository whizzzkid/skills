## Session-3

### What worked
- Cross-checking a "resolved" bot thread's claimed fix against branch history caught a fix that was silently lost in a rebase (the cited commit was not on the branch).
- Anchoring inline comments on a newly-added file is safe since every line is in the diff's commentable set.

### What could've been better
- pr-review: a new `docs/(specs|adr|arch|design|rfc)/` file is an unconditional arch-review trigger — grep the changed-file list mechanically in Phase 1, never treat it as a judgment call.
- pr-review: opening the review html_url is a non-optional final action on every review create/recreate — a jq parse error on the create response must not drop it.
- pr-review: the REST comments endpoint cannot attach to an existing pending review (422 one-pending-review); to add comments, delete and recreate the pending review with the full comment set in one POST.
