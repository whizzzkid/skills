## Session-1

### What worked
- Fake binary injection via PATH (writing fake `git`, `gh`, `curl` scripts to a tmpdir prefixed onto PATH) is the right test-isolation pattern when the script's behavior depends on external command output that varies with system config.
- Fail-open design for missing actor identity (warn + continue) keeps downstream processing unblocked while surfacing the gap in logs.
- Adversarial review subagent found zero blockers cleanly; using `Open3.capture3` with array-form args eliminated all shell-injection risk up front.

### What could've been better
- workflow: When adding RFC-2822 actor/author identity to an external tool call, read from git commit metadata (`git log --pretty="%aN <%aE>"`) rather than constructing from API responses — the commit history is the authoritative source of author identity in a git-based CI pipeline.
- workflow: Multi-subprocess layer test design: when a script captures inner process output via `Open3.capture3`, that inner stderr is NOT forwarded to the outer process stderr on success; assert on the outer script's own stdout/stderr output, not the inner process args.
