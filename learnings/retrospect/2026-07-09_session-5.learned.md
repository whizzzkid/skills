## Session-5

### What worked
- Applying a flagged issue class uniformly across all structurally-identical siblings (not just the one line the reviewer cited) kept the schema internally consistent and pre-solved siblings the reviewer would have flagged next.
- When a migration adds a load-bearing invariant, locking it in the repo's schema-guard spec in the same session prevents silent future regression.

### What could've been better
- pr-resolve: two already-distilled rules — fetch all three feedback surfaces before triage, and pre-check the author's pending self-review at fetch time — both failed to steer, so a whole bulk-findings surface was missed until the user asked and a pending-review 422 was hit at reply time; the rules need stronger in-flow enforcement, not another duplicate learning.
- pr-resolve: the PR body was replaced via a whole-body edit without first capturing the original, so drop-detection was only possible against the reconstruction.
