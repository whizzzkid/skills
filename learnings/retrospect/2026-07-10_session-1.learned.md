## Session-1

### What worked
- Detecting an author's PENDING self-review up front and routing thread resolution through GraphQL (not a REST reply) avoids the 422 that a review-comment reply hits while a pending review exists.
- Isolating one bot finding into its own commit by temporarily editing the added lines back out, staging the rest, committing, then re-adding — clean per-triage-unit history without interactive `git add -p`.

### What could've been better
- pr-resolve: on a finding that docs describe behavior the diff doesn't implement, check for a stacked/follow-up PR owning it and default to future-tense wording rather than pulling that scope forward (routed to wk-learn).
- adversarial-review: a config-key/symbol rename that greps clean in the tree can still leave the PR body pointing at old names and a stale test count — grep the body, not just the working tree (routed to wk-learn).
