## Session-2

### What worked
- Diagnosing a real (non-flaky) CI failure by tracing it to the exact commit that introduced it (comparing a prior green build's log against the current failing one) before reaching for a suppression file.
- Scoping a Brakeman false-positive suppression narrowly (one fingerprint + rationale) instead of reverting a correctness-motivated refactor.

### What could've been better
- wk-buildkite / devcontainer workflow: when `devcontainer up`/`docker compose up` fails on a host port already bound by another worktree's running stack, the skill has no documented fallback — joining the project's existing Docker network/named volumes via a direct `docker run` (no host port publish) worked but had to be discovered ad hoc.
- wk-buildkite: Cloudsmith-backed `bundle install` inside a manually-started container needs `BUNDLE_DL__CLOUDSMITH__IO="token:$CLOUDSMITH_API_KEY"` (the exact var name from `post-create.sh`), not a generic `CLOUDSMITH_API_KEY` env var alone — this cost a failed attempt before the docs were re-read.
