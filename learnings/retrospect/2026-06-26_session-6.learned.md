## Session-6

### What worked
- Systematic root-cause analysis using API timing data (authoredDate vs committedDate) to pinpoint exactly why the commit count was wrong — avoided guessing and found the real gap in context.
- Parallel tool calls throughout reduced round-trips significantly on research-heavy phases.
- Adversarial review surfaced two gaps before PR was marked ready: missing guard test for the `can_fetch_pr_data?` short-circuit path, and reviewer skill instruction not referencing the new commits field.

### What could've been better
- wk-workstyle-ruby: RuboCop failures (Layout/FirstMethodArgumentLineBreak, Style/AsciiComments) were only caught by CI, not pre-commit. Running `bundle exec rubocop` before staging would have eliminated a fix cycle.
- wk-adversarial-review: The reviewer skill update (adding instruction to use commits list) and the guard test were caught reactively by adversarial review rather than proactively during implementation — the pattern of updating adjacent skills/prompts alongside code changes should be part of the implementation checklist.
