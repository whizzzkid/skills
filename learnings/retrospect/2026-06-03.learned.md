## Session-1

### What worked
- Adversarial subagent caught the security footgun (silent empty `InstallationPermissions{}` sends grant-all to the API) before the first push — exactly the class of issue the pre-flight gate exists for.
- Progressive CI failure isolation: each build failure (gofmt, hk musl, yamlfmt, yamllint) was diagnosed from logs and fixed atomically with a targeted commit.
- JSON `DisallowUnknownFields` pattern: using the library struct's own tags as the validation source rather than a parallel allowlist — learned from user correction, generalises to any typed external-API client.

### What could've been better
- wk-pr: base-detection step existed in the skill but was skipped before `gh pr create`; PR landed against wrong base and had to be recreated.
- wk-workstyle-go: no explicit `gofmt -l .` gate before commit; map literal alignment failed CI lint on the first push.
- workflow: adversarial review correctly identified a security gap but the fix over-engineered it (40-entry hardcoded allowlist) instead of using the library struct's JSON tags with `DisallowUnknownFields`.

Learnings routed to wk-learn: pr (resolve-true-base-before-create), workstyle-go (gofmt-before-commit), workflow (avoid-hardcoded-api-allowlists).
