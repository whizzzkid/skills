## Session-1

### What worked
- Bulk-queue + single judgment-required consultation kept the resolve cycle to one round with minimal ceremony.
- GraphQL thread node IDs (`PRRT_...`) survived a post-push REST ID expiry and resolved all threads cleanly; REST 404s on replies are expected and non-fatal.

### What could've been better
- wk-adversarial-review: verify the external API's error-response schema (key name) before asserting which field encodes the failure; a missing `web_url` + missing `error` key combination caused silent failure in skill instructions.
- wk-adversarial-review: prose "warn the user" notes in skill instructions are likely to be omitted; require an explicit imperative output block when the warning matters for user safety.
## Session-2

### What worked
- GraphQL thread IDs (`PRRT_...`) reliably survived every post-push REST ID expiry across multiple resolve cycles; the 404-recovery pattern is now a reliable default, not a fallback.

### What could've been better
- wk-adversarial-review: the "docs-only" exemption was applied to a resolve-cycle push whose diff was entirely skill instruction files — those files are executable specifications and the subagent found real logic bugs (jq null guard, naming ambiguity) that it would have caught had it been dispatched.
- wk-adversarial-review: sweep 2.3 (guard reachability) must probe jq filter output shapes (string "null" for JSON null fields) not just guard existence; a guard that catches empty string but not jq-null silently passes invalid values downstream.
## Session-3

### What could've been better
- wk-curl (new): `curl -s` silences transport-level errors — `-sS` plus exit-status capture is the correct idiom for any curl call whose response is parsed; this was knowable at write-time from documentation and should have been applied on first authoring.
- wk-learn: tool/CLI-specific learnings should route to a dedicated `wk-<tool>` skill (model-invocable) rather than the triggering skill bucket; this prevents curl/jq/gh quirks from being buried in review-process learnings.
## Session-4

### What worked
- Reproducing a suspected nondeterminism (VCS stamping) in a throwaway playground before pushing turned a would-be CI flake into a one-line fix with evidence.
- A parity gate that samples the live data file (every Nth row, capped in awk) keeps a port-vs-reference test matrix from going stale without hardcoding fixtures.
- Verifying the browser surface with a real headless-browser session (load, resolve, toggle, malformed input) caught the JSON null-vs-empty-array shape mismatch before it shipped.

### What could've been better
- buildkite: verify an internal registry mirror actually carries an image repo before pinning a CI step to it — mirrors are not necessarily pull-through.
- adversarial-review: a correctness flag added to one toolchain invocation must be swept across all sibling invocations repo-wide; linked worktrees can mask VCS-dependent behavior locally.
- workflow: re-run every gate a newly added CI step will run against final HEAD before push — files added after the last local lint run silently skip it.
## Session-5

### What worked
- The thrash-detection call ("the bot is contradicting its own accepted findings") gave the user the signal to terminate a non-converging review loop; the exit condition for an LLM reviewing an instruction file is a human decision, not bot silence.
- Dismissal replies citing the bot's own prior contradictory findings made each dismissal self-evidencing.

### What could've been better
- wk-adversarial-review: a new `trap` registration must grep the whole file for existing traps on overlapping signals — bash trap replaces, so two correct fixes in separate rounds silently combined into a cleanup leak.
- wk-pr-resolve: a review loop where round-over-round finding counts increase (not decrease) and findings start reversing accepted fixes is terminal thrash — surface a merge recommendation rather than another fix cycle.
## Session-6

### What worked
- Cherry-picking specific commits onto a fresh branch from main cleanly resolves stacked-PR mis-merge without a full rebase.
- Using a fixed tarball filename (with version in the metadata field) produces a stable "latest" download URL for Cloudsmith raw packages.

### What could've been better
- wk-pr: base-detection starts DEFAULT_BRANCH at BEST_DIST=999999 but never measures its actual distance — any open-PR branch with a finite measured distance wins, even when it's further. Measured distance to default branch must also be computed in the loop.

## Session-7

### What worked
- Orientation check (pr-takeover Step 4) caught 3 unresolved self-review threads that would have blocked branch protection — resolving them via GraphQL cleared the PR cleanly.

### What could've been better
- wk-pr-resolve: after `wk-self-review` is submitted, the resulting threads are left unresolved — the PR-resolve orientation pass should proactively resolve the author's own self-review threads since branch protection counts every unresolved thread with no author exclusion.
